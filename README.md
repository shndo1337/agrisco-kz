# AgriScore KZ
**AI-система merit-based скоринга сельхозпроизводителей для распределения субсидий**

## Проблема

Сегодня государственные субсидии для сельхозпроизводителей Казахстана распределяются по принципу **«первый подал — первый получил»**: финансирование уходит тому, кто раньше собрал пакет документов, пока не закончился бюджет. Реальная эффективность хозяйства, история использования предыдущих субсидий и потенциал к росту **не учитываются**.

### Масштаб проблемы (данные 2025)

| Метрика | Значение |
|---------|----------|
| Одобрено заявок с баллом AgriScore < 50 | **~4 400** (15.3% от одобренных) |
| Бюджет на слабых заявителей | **~12.5 млрд ₸** — потенциально неэффективно |
| Отклонено достойных заявок (балл ≥ 60) | **~86** на сумму ~171 млн ₸ |
| Разброс одобрений по регионам | **64 п.п.** (от ~29% до ~93%) — субъективность |

> При merit-based скоринге ~3 400 слабых заявок были бы заменены на более достойных с выигрышем **+28.5 баллов** в среднем, при том же бюджете.

Министерство хочет перейти к **merit-based скорингу** — распределению субсидий на основе данных о производителях, а не по принципу очерёдности.

## Решение

AgriScore KZ — AI-система, которая заменяет принцип очереди на **data-driven ранжирование** с двумя компонентами:

### Композитный скоринг (60% ML + 40% Rules)

- **ML-компонент** — ансамбль XGBoost + LightGBM, обученный на 31,536 размеченных заявках с 30 инженерными признаками
- **Rule-based компонент** — 9 экспертных правил на основе 3 НПА МСХ РК: Правила субсидирования (Приказ №108, ред. №428), Нормы падежа (Приказ №3-3/1061), Нормы нагрузки на пастбища (Приказ №3-3/332, ред. №394)
- **Explainability** — SHAP-анализ каждого ML-фактора + разбивка rule-based компонентов + текстовое объяснение на русском языке

### Возможности системы

- **Скоринг заявителей** — каждая заявка получает балл от 0 до 100
- **Шорт-лист для комиссии** — автоматическое формирование списка лучших кандидатов с экспортом в CSV
- **What-If симулятор** — изменение параметров заявки в реальном времени с пересчётом балла
- **Загрузка новых заявок** — комиссия загружает CSV → получает ранжированный список
- **Аналитический дашборд** — визуализация по областям, направлениям, сравнение ML vs Rule компонентов

> AI помогает принимать решения, но **не заменяет эксперта**. Финальное решение всегда остаётся за комиссией.

## Данные

- **Источник**: Выгрузка из ИСС (subsidy.plem.kz) — 36,651 заявок на субсидии племенного животноводства за 2025 год
- **Области**: 18 областей Казахстана
- **Направления**: 9 направлений (скотоводство, птицеводство, овцеводство, коневодство, верблюдоводство и др.)
- **Типы субсидий**: 45+ видов субсидий
- **Target**: статус заявки (Одобрена/Исполнена vs Отклонена) — 31,536 размеченных записей

### Engineered Features (30 признаков)

| Группа | Признаки |
|--------|----------|
| Числовые (log) | Сумма, норматив, кол-во голов |
| Текстовые флаги | Импорт, племенная работа, селекция, молоко, мясо, птица, молодняк, покупка, корма |
| Категориальные | Область, район, направление, тип субсидии |
| Временные | Месяц, час, Q1 |
| Региональные агрегаты | Средняя сумма по области, доля одобренных, кол-во заявок, средняя по району |
| Ratios | Сумма/средняя по области, норматив/средний по направлению, головы/среднее по области |

## Метрики модели

### Baseline Comparison (5-fold CV ROC-AUC)

| Модель | CV ROC-AUC | Обоснование |
|--------|-----------|-------------|
| Logistic Regression | ~0.79 | Линейный baseline |
| Random Forest | ~0.82 | Нелинейный baseline |
| XGBoost | 0.844 | Основной компонент |
| LightGBM | 0.838 | Второй компонент |
| **Ensemble (55/45)** | **~0.847** | **Финальная модель** |

> Ensemble стабильно превосходит каждый компонент: усреднение снижает дисперсию.

### Метрики финальной модели

| Метрика | Значение |
|---------|----------|
| Full ROC-AUC | **0.940** |
| Accuracy | 0.81 |
| F1 (Одобрена) | 0.88 |
| Recall (Отклонена) | 0.93 |
| Precision (Отклонена) | ~0.32 |

> 5-fold stratified CV. Дисбаланс классов учтён через `scale_pos_weight`.

**Precision/Recall trade-off:** Низкий precision «Отклонена» (~32%) при recall 93% — осознанный выбор. Система рекомендательная: лучше пометить сомнительную заявку для проверки (ложная тревога), чем пропустить слабую (пропущенный риск). Порог настраивается.

### Ablation Study

| Компонент | ROC-AUC | Роль |
|-----------|---------|------|
| ML-only (Ensemble) | ~0.94 | Паттерны в данных |
| Rules-only (9 НПА) | ~0.55-0.65 | Юридическая обоснованность |
| **Composite (60/40)** | **~0.93** | Баланс качества и обоснованности |

> ML и Rules дополняют друг друга: ML ловит нелинейные паттерны, Rules обеспечивают соответствие НПА. Подробный анализ — в `notebooks/03_model_analysis.ipynb`.

## Explainability

Каждая заявка получает три уровня объяснения:

**1. Композитный балл** (0–100) = 60% ML + 40% Rule-based

**2. SHAP waterfall** — вклад каждого ML-фактора + разбивка rule-компонентов:

```
Итоговый балл: 90.2/100
  ML-компонент: 97.8  |  Rule-компонент: 78.7
  (60% ML + 40% Rules)

Положительные факторы:
  + Селекционная работа (+1.345)
  + Доля одобренных по области (+1.199)
  + Область (+0.393)
Факторы риска:
  - Месяц подачи (-0.208)
```

**3. Rule-based разбивка** — 9 нормативных компонентов с визуализацией:
- Тип субсидии (0–30): приоритет племенной работы
- Норматив (0–25): качество поголовья
- Соответствие НПА (0–10): соответствие официальным нормативам Приложения 1
- Размер стада (0–15): масштаб хозяйства
- Направление (0–10): приоритет отрасли
- Регион (0–10): региональный баланс
- Сезонность (0–10): оптимальность сроков
- Устойчивость к падежу (0–10): 34 нормы по виду/возрасту/транспортировке
- Пастбищная база (0–10): нагрузка на пастбища по 18 областям

## Rule-based компонент

Основан на **3 нормативно-правовых актах МСХ РК**:

1. **Правила субсидирования** (Приказ №108, ред. №428 от 18.11.2025) — приоритеты типов субсидий, официальные нормативы (Приложение 1), требования к заявителям
2. **Нормы падежа** (Приказ №3-3/1061) — 34 детализированных нормы естественной убыли по виду, возрасту, способу транспортировки
3. **Нормы нагрузки на пастбища** (Приказ №3-3/332, ред. №394) — предельно допустимая нагрузка по 18 областям и 4 видам животных

9 компонентов скоринга (макс. 130 баллов → нормализация в 0-100):
- **Тип субсидии** (0–30): селекционная работа > приобретение > удешевление > корма
- **Норматив** (0–25): ценное племенное поголовье (импорт > отечественное)
- **Соответствие НПА** (0–10): отклонение от официального норматива → штраф
- **Размер стада** (0–15): масштаб хозяйства
- **Направление** (0–10): приоритет по отрасли
- **Регион** (0–10): бонус недообеспеченным регионам
- **Сезонность** (0–10): оптимальные сроки по типу животноводства
- **Устойчивость к падежу** (0–10): риск падежа по нормам НПА
- **Пастбищная база** (0–10): достаточность пастбищных угодий

## Как интерпретировать результаты (для комиссии)

### Что означает балл?

| Балл | Зона | Рекомендация комиссии |
|------|------|----------------------|
| **70–100** | Зелёная | Высокий приоритет. Заявка соответствует НПА, сильные показатели по всем компонентам. Рекомендуется к одобрению. |
| **40–69** | Жёлтая | Средний приоритет. Есть факторы риска — рекомендуется ручная проверка по SHAP-разбивке (вкладка «Детали»). |
| **0–39** | Красная | Низкий приоритет. Значимые расхождения с НПА или слабые показатели. Рекомендуется отклонение или доработка. |

### Из чего складывается балл?

```
Итоговый балл = 60% × ML-балл + 40% × Rule-балл
```

- **ML-балл** — предсказание ансамбля XGBoost + LightGBM на основе 30 признаков (сумма, норматив, регион, направление, сезонность и др.). Показывает, насколько заявка похожа на ранее одобренные.
- **Rule-балл** — экспертная оценка по 9 нормативным критериям из 3 приказов МСХ РК. Показывает соответствие законодательству.

### Как пользоваться SHAP-объяснениями?

Во вкладке **«Детали»** для каждой заявки показан waterfall-график:
- **Зелёные полосы** (вправо) — факторы, повышающие балл (например, «Племенная работа +1.3»)
- **Красные полосы** (влево) — факторы риска (например, «Месяц подачи -0.2»)
- Чем длиннее полоса, тем сильнее влияние фактора

Это позволяет объяснить заявителю **конкретную причину** решения.

### Как пользоваться шорт-листом?

1. Выберите количество кандидатов (ползунок)
2. Система покажет топ-N заявок с наивысшим баллом
3. Скачайте результат в **CSV** (для дальнейшей работы) или **PDF** (для протокола комиссии)

> **Важно:** система носит **рекомендательный характер**. Финальное решение всегда остаётся за комиссией. AI помогает ранжировать и объяснять, но не заменяет эксперта.

## Ограничения решения

### Ограничения данных
- **Обезличенный датасет** — нет ID производителя, невозможно агрегировать историю заявителя (повторные обращения, предыдущие результаты)
- **Только 2025 год** — для продакшена необходимо периодическое дообучение на актуальных данных
- **Нет данных о причинах отклонения** — модель не знает, была ли заявка отклонена из-за качества или из-за формальных нарушений (неполный пакет документов)
- **Нет финансовых показателей хозяйства** — выручка, рентабельность, кредитная история отсутствуют в датасете

### Ограничения модели
- **ML обучен на субъективных решениях FCFS** — модель частично воспроизводит предвзятость исторических данных; rule-based компонент (40%) смягчает этот эффект
- **Precision класса «Отклонена» ~32%** — модель пересберегает (лучше перепроверить сомнительную заявку). Порог настраивается при необходимости
- **Rule-based** покрывает основные критерии 3 НПА, но не все положения Приложения 2 (часть требует данных, отсутствующих в датасете)

### Ограничения развёртывания
- Для полноценного production-развёртывания необходимы: мониторинг drift модели, A/B тестирование с текущей системой, интеграция с ИСС (subsidy.plem.kz)
- Система не заменяет комиссию — носит **рекомендательный характер**
